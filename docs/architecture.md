# 系统架构

EcomFlow 是同步执行的单机应用。CLI 负责参数和退出码，任务执行器负责生命周期，业务服务编排操作，适配器承担平台协议转换，存储层提供明确事务边界。

## 模块边界

- `core/models.py`：Pydantic 标准商品、订单明细、订单及账单模型；金额从十进制文本构造 Decimal，拒绝 float。
- `ingestion/products.py`：字符串读取 CSV/Excel、字段整理、SKU 去重、逐行校验、错误报告和原始行追踪。
- `adapters/platforms.py`：统一接口暴露发布和分页订单读取；平台 A/B 的字段差异不泄漏到公共服务。
- `clients/api.py`：Requests Session、连接/读取超时、错误分类、有限重试及业务 ID 日志。
- `services/`：产品发布、订单同步和对账。
- `database/store.py`：schema、外键、索引和事务上下文，业务代码通过参数化 SQL 写入。
- `jobs/tasks.py`：独立事务记录任务状态，业务事务失败后任务审计仍能提交。
- `reports/`：导出运行状态；对账服务导出结果和关联源数据。

## 可靠性选择

只对 GET 和显式具备幂等键的写请求重试。默认最多重试 2 次，加上首次共 3 次；退避为 0.1、0.2 秒，上限 2 秒。遇到 Retry-After 秒数或 HTTP 日期取较大的等待时间，超过 10 秒预算时停止并保留失败，避免无上限阻塞。401、普通 4xx、非法 JSON、响应字段契约错误不自动重试。

发布使用 `platform:sku` 作为稳定幂等键。模拟平台缓存键及请求摘要，相同键相同数据返回相同结果，不同数据返回 409。发布记录成功后跳过再次发布；商品更新是独立的后续扩展，不隐式复用发布接口。

订单按平台和订单 ID upsert，明细事务内替换。分页失败会回滚已处理页面和游标。商品输入支持部分成功，整行错误保留到审计和 Excel，而整批状态记为 FAILED。

## 运行和资源

只需一个 Python 进程执行命令及一个本地 Uvicorn 服务。自动 demo 通过子进程启动临时 API，健康检查成功后执行，并在 finally 中终止自身启动的进程。SQLite 无独立部署成本，适合可复现面试演示。

## 范围

不实现真实平台认证、分布式锁、定时调度或多实例一致性。把这些能力作为后续需求，可以避免为了展示引入无法解释的复杂基础设施。
