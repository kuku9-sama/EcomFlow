# 面试问题与回答

## 1. 为什么选择 SQLite？

第一版目标是单机可复现演示。SQLite 支持事务、外键和唯一约束，无需额外服务；并发写入能力有限，生产多执行器可迁移 PostgreSQL，并缩短同步写事务。

## 2. 为什么金额不能用 float？

二进制浮点无法精确表示 0.1 等十进制金额，累积后可能产生虚假对账差异。输入以字符串读取并构造 Decimal，数据库以 TEXT 保存，报告也输出十进制文本。

## 3. 如何防止重复发布？

本地用 platform+sku 唯一约束和成功状态跳过，HTTP 使用稳定幂等键。服务端记录幂等键和请求摘要，丢失响应后重试不会创建第二条商品。商品更新应有独立接口，不能隐式改变同一个发布键的内容。

## 4. 何时可以重试 POST？

只有服务端明确支持幂等键等去重机制时。默认 POST 不重试；401 和非法 JSON 不盲目重试，429/5xx/传输异常在安全请求上有限重试。Retry-After 超出预算时记录失败交由后续恢复。

## 5. 如何保证重复同步不产生重复订单？

订单唯一键为平台+平台订单 ID，采用 upsert；明细在同一事务内替换。游标只在所有页面成功后提交。失败回滚后可以完整重放。

## 6. 增量同步有什么边界？

时间戳游标要求上游数据完整且时间一致；迟到数据或同时间记录变更可能遗漏。下一版采用平台稳定游标，或重叠时间窗口加唯一键去重，并为分页建立快照语义。

## 7. 重复账单为什么不在导入时删除？

重复本身就是财务差异证据。以来源和行号保证重复导入幂等，同时保留同一订单的多行账单用于识别。当前按订单整单结算，不支持合法多次分批结算。

## 8. 如何区分运行失败和业务差异？

HTTP 失败、输入错误导致任务 FAILED。对账成功生成报告为 SUCCESS，报告内部可以存在金额差异。样例商品错误是预期演示，保留真实 FAILED 状态，不修改断言或伪装全部成功。

## 9. 为什么不用 Celery 和 Redis？

目前没有后台异步调度和多工作进程需求。同步 CLI 更容易演示与定位错误。未来需要调度时，可保留服务和任务接口，增加队列消费者。

## 10. 测试如何证明可运行？

不仅验证映射，还真实启动 Uvicorn，通过 Requests 执行双平台业务和故障注入。完整 demo 连续执行两次，断言稳定业务计数、真实 Excel 和持久化失败记录。

## 11. 为什么任务日志独立提交？

业务事务失败时必须回滚业务数据，但失败审计仍需保留。任务状态使用独立短事务提交；SQLite 单写者限制意味着不能在持有业务事务时从另一个连接同时写任务日志。

## 12. 如何扩展第三个平台？

新增统一适配器的实现，定义请求字段、响应解析和状态映射，在工厂注册，并增加契约测试。公共发布、同步和对账服务保持标准模型接口。
